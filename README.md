# Policy Check

Compares an expiring commercial package policy against its renewal and reports what changed —
limits, deductibles, forms, endorsements, and risk-transfer terms — with a page citation and a
verbatim source snippet behind every finding.

Materiality is decided by deterministic rules. The model extracts and narrates; it never rules
on whether a change matters. The tool describes changes; a licensed professional interprets
them.

**Line of business:** commercial package — General Liability + Commercial Property.
**Status:** spec and scaffold. No implementation yet.

- [`spec.md`](spec.md) — the product spec. §2 invariants are locked.
- [`.spec/plan.md`](.spec/plan.md) — module map and build sequence.

## Documents you need

**The corpus is not in this repo.** A clone gives you the code and the ground-truth manifests,
not the policies. Source documents are large, and some carry redistribution restrictions — so
`corpus/raw/`, `corpus/base/`, and `corpus/renewal/` are git-ignored while
`corpus/pairs/*/manifest.json` is tracked. Ground truth is versioned; source documents aren't.

You need to assemble these yourself before anything downstream can be validated.

### What counts as a usable document

A **complete commercial package policy** — not a certificate, not a quote, not a dec page on
its own. All three parts:

1. **Declarations page** — named insured, policy period, carrier, limits, deductibles,
   property locations and their values.
2. **Forms schedule** — the list of every form and endorsement attached, with edition dates.
3. **The endorsements themselves** — the actual attached form pages.

A dec page alone can't exercise most of the findings taxonomy. Roughly half the findings that
matter — additional insured scope, waiver of subrogation, primary & non-contributory, added
exclusions, form edition changes — live in the endorsements.

### Where to find them

All public. No client dependency.

| Source | What it yields | How to search |
|---|---|---|
| **CourtListener / RECAP** | Complete policies filed as litigation exhibits. Best source — coverage disputes attach the entire policy. | Full-text search for `"commercial general liability" declarations endorsement` |
| **Public entity procurement** | Dec pages, certificates, occasionally full policies in board packets and RFP attachments | `site:.gov filetype:pdf "declarations" "commercial general liability"` |
| **State risk pools / JPAs** | Full coverage documents, published as a matter of policy | Search individual pool sites directly |
| **SERFF public filing access** (state DOI) | Form filings | Availability varies by state |
| **Carrier specimen policies** | Clean, complete specimens | More common in professional liability, cyber, surplus lines |

> **ISO forms are licensed by Verisk and are not a public library.** Individual ISO forms
> appearing inside the documents above are fine to process. Do not build sourcing around
> obtaining a form catalog.

### How many, and of what kind

Target **15–20 base documents**, yielding **20 renewal pairs**:

- **3–5 distinct carriers.** Form numbering and dec-page layout vary enough between carriers
  that a normalizer tuned on one will fail on the next.
- **≥2 with scanned / image-only pages.** Extraction on scanned carrier PDFs is the main
  technical risk. Get these in early rather than discovering the problem at an event.
- **≥4 where the only material change is subtle** — an edition date, an additional-insured
  scope narrowing. These are the demo moments.
- **≥2 with no material changes at all.** The tool has to be able to say "nothing material
  changed."

### Where to put them

```
corpus/
├── raw/                       # as-downloaded, untouched          (git-ignored)
├── base/<doc_id>.pdf          # working copy, expiring side       (git-ignored)
├── renewal/<pair_id>-renewal.pdf   # generated by pairgen         (git-ignored)
├── ledger.json                # provenance, one entry per document
└── pairs/<pair_id>/manifest.json   # ground truth                 (tracked)
```

Register each document as you add it — this records page count and whether any page lacks a
text layer:

```bash
uv run pc corpus add path/to/policy.pdf --source courtlistener --url https://...
uv run pc corpus status     # coverage against the targets above
```

Every entry needs a `source_url` a stranger could follow. If it can't be re-fetched publicly,
it doesn't belong in the corpus.

### Renewal pairs are generated, not found

Public sources yield single policies, never expiring/renewal pairs. Renewals are authored: a
manifest lists controlled changes (limit decrease, endorsement removed, valuation downgrade,
form edition rollback…) plus decoys that must *not* be flagged adverse (premium change, address
change, agent of record change). `pairgen` patches the real PDF in place, so the renewal keeps
the carrier's real layout and scan artifacts.

That manifest is the ground truth the eval harness scores against. Manifest format:
[`spec.md` §3.2](spec.md).

## Setup

Requires Python 3.13, [uv](https://docs.astral.sh/uv/), Node 22+, and Postgres 16 (the pipeline
itself runs without Postgres — it's only needed for the API and demo cache).

```bash
uv sync
export ANTHROPIC_API_KEY=...
```

Checks that must stay clean:

```bash
uv run ruff check .
uv run pyright
uv run pytest
uv run alembic check      # after any model change
```

## Pipeline

Every stage runs standalone from the CLI before it has a UI.

```bash
uv run pc extract policy.pdf              # PDF  -> PolicySnapshot (dual pass, cited)
uv run pc compare prior.json renewal.json # two snapshots -> findings
uv run pc report run.json --client        # findings -> renewal difference summary
uv run pc eval run                        # full manifest set -> scorecard
```
